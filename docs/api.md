# API Reference

The wire contract is [`api/proto/hue/v1/hue.proto`](../api/proto/hue/v1/hue.proto).
Every RPC has a `google.api.http` annotation, so every gRPC method is
also reachable as a REST endpoint via grpc-gateway. Both transports
hit the same Go function through the same interceptor chain (panic
recovery, structured logging, auth, authorization, protovalidate).

The OpenAPI spec generated by `make proto` is at
`gen/openapi/hue.swagger.json` and gets attached to every release as
a build artifact. The same spec is embedded in the binary and served
at runtime — see [Built-in Swagger UI](#built-in-swagger-ui).

## Services

| Service | Principals | Surface |
|---|---|---|
| **AuthService**              | anonymous              | `Login` / `Logout` / `Refresh` / `ChangePassword` |
| **AdminService**             | Owner                  | Node + Agent CRUD + Events + Health |
| **AuthAdminService**         | Owner                  | API key CRUD |
| **ResellerClientService**    | Reseller, Owner        | Client CRUD + UsagePlan reads + available-nodes |
| **ResellerManagementService**| Reseller, Owner        | Sub-Reseller CRUD (descendants only — non-Owner) |
| **ConfigService**            | Agent                  | Per-Node `SyncConfig` + `Heartbeat` |
| **DomainCertificateService** | Owner writes, Reseller+Owner reads | BYO + ACME + Self-signed |
| **UsageService**             | Agent                  | `ReportUsage` / `BatchReportUsage` / `SyncClients` |

Positive authorization runs in
[`internal/server/authz.go`](../internal/server/authz.go): each RPC
has an explicit `(FullMethod → allowed PrincipalKinds)` entry;
mismatch returns `PermissionDenied`. Anonymous routes are listed in
`Authenticator.AllowMethods`.

## Conventions

- Resource collections at `/v1/<plural>` (`/v1/clients`,
  `/v1/resellers`, `/v1/nodes`, `/v1/agents`, `/v1/apiKeys`,
  `/v1/events`, `/v1/usagePlans`, `/v1/domainCerts`).
- Updates use `PATCH` with `google.protobuf.FieldMask` (`update_mask`).
- Custom verbs follow AIP-136: `:login`, `:refresh`, `:logout`,
  `:changePassword`, `:resetUsage`, `:revoke`, `:report`,
  `:batchReport`, `:sync`, `:syncConfig`, `:heartbeat`,
  `:requestACME`, `:availableInfo`, `:stream`.
- Pagination: `page_size` + `page_token` in requests;
  `next_page_token` in responses.
- Authentication: `Authorization: Bearer <token>` over HTTP, or
  `authorization: Bearer <token>` gRPC metadata. See [auth.md](auth.md).

## REST routes (current)

### AuthService — anonymous

| RPC | Verb / path |
|---|---|
| `Login`          | `POST /v1/auth:login` |
| `Logout`         | `POST /v1/auth:logout` |
| `Refresh`        | `POST /v1/auth:refresh` |
| `ChangePassword` | `POST /v1/auth:changePassword` |

### ResellerClientService — Reseller, Owner

| RPC | Verb / path |
|---|---|
| `CreateClient`           | `POST /v1/clients` (body=`client`) |
| `GetClient`              | `GET /v1/clients/{id}` |
| `ListClients`            | `GET /v1/clients` |
| `UpdateClient`           | `PATCH /v1/clients/{id}` (body=`client`) |
| `DeleteClient`           | `DELETE /v1/clients/{id}` |
| `ResetClientUsage`       | `POST /v1/clients/{client_id}:resetUsage` |
| `GetUsagePlan`           | `GET /v1/usagePlans/{id}` |
| `ListUsagePlans`         | `GET /v1/usagePlans` |
| `GetActiveUsagePlan`     | `GET /v1/clients/{client_id}/activeUsagePlan` |
| `GetAvailableNodesInfo`  | `GET /v1/nodes:availableInfo` |

Non-Owner callers are scoped to the descendants of their own
Reseller (BFS over `Reseller.parent_id`). Owner sees every Reseller's
Clients.

### ResellerManagementService — Reseller, Owner

| RPC | Verb / path |
|---|---|
| `CreateReseller`     | `POST /v1/resellers` (body=`reseller`) |
| `GetReseller`        | `GET /v1/resellers/{id}` |
| `ListResellers`      | `GET /v1/resellers` |
| `UpdateReseller`     | `PATCH /v1/resellers/{id}` (body=`reseller`) |
| `DeleteReseller`     | `DELETE /v1/resellers/{id}` |
| `ResetResellerUsage` | `POST /v1/resellers/{reseller_id}:resetUsage` |

Same descendant scoping as `ResellerClientService`. A Reseller cannot
see or modify peers; only its sub-tree.

### AdminService — Owner only

| RPC | Verb / path |
|---|---|
| `CreateNode` / `GetNode` / `ListNodes` / `UpdateNode` / `DeleteNode` / `ResetNodeUsage` | `/v1/nodes…` |
| `CreateAgent` / `GetAgent` / `ListAgents` / `UpdateAgent` / `DeleteAgent` | `/v1/agents…` |
| `ListEvents`     | `GET /v1/events` |
| `StreamEvents`   | `GET /v1/events:stream` (server-streaming over chunked HTTP) |
| `HealthCheck`    | `GET /healthz` (also implements `grpc.health.v1.Health`) |

`StreamEvents` is live — server-sent fan-out from the eventstore subscriber
bus. Supports filters: `types`, `client_id`, `reseller_id`, `buffer_size`.

### AuthAdminService — Owner only

| RPC | Verb / path |
|---|---|
| `CreateApiKey` | `POST /v1/apiKeys` — response carries plaintext `token` once |
| `ListApiKeys`  | `GET /v1/apiKeys` |
| `RevokeApiKey` | `POST /v1/apiKeys/{id}:revoke` |

### ConfigService — Agent only

| RPC | Verb / path |
|---|---|
| `SyncConfig` | `GET /v1/nodes/{node_id}:syncConfig` |
| `Heartbeat`  | `POST /v1/nodes/{node_id}:heartbeat` |

`SyncConfig` resolves the Agent's `node_id` from the API key and
rejects a `request.node_id` mismatch with `PermissionDenied`. See
[phase2-changes.md → ConfigService](phase2-changes.md#configservice--per-node-config--version-selection).

### DomainCertificateService

| RPC | Verb / path | Auth |
|---|---|---|
| `AddCertificate`    | `POST /v1/domainCerts`              | Owner |
| `GetCertificate`    | `GET /v1/domainCerts/{domain}`      | Reseller, Owner |
| `ListCertificates`  | `GET /v1/domainCerts`               | Reseller, Owner |
| `DeleteCertificate` | `DELETE /v1/domainCerts/{id}`       | Owner |
| `RequestACME`       | `POST /v1/domainCerts:requestACME`  | Owner |

Private-key PEM is redacted for non-Owner reads. `RequestACME`
returns `Unimplemented` when `HUE_ACME_CONTACT_EMAIL` is empty. See
[certificates.md](certificates.md).

### UsageService — Agent only

| RPC | Verb / path |
|---|---|
| `ReportUsage`      | `POST /v1/usage:report` (body=`report`) |
| `BatchReportUsage` | `POST /v1/usage:batchReport` |
| `SyncClients`      | `GET /v1/clients:sync` |

## Built-in Swagger UI

Every running instance ships with a browsable API explorer.

| URL | What it serves |
|---|---|
| `/swagger` | 301 → `/swagger/` |
| `/swagger/` | Swagger UI 5.x — interactive explorer |
| `/docs` | 301 → `/swagger/` (alias) |
| `/openapi.json` | Raw OpenAPI v2 spec, augmented with a `bearer` security scheme so the **Authorize** button works |
| `/swagger-ui/` | Vendored Swagger UI JS/CSS (`make swagger-ui-update` refreshes) |

Open `https://your-host:8443/swagger/` in a browser, click
**Authorize**, paste `Bearer <your-token>`, then "Try it out" against
any endpoint. `persistAuthorization: true` keeps the token across
reloads.

These four paths (`/openapi.json`, `/swagger/`, `/docs`,
`/swagger-ui/`) are intentionally **unauthenticated** — schema only.
The challenge endpoint at `/.well-known/acme-challenge/` is also
public for ACME validation.

## End-to-end example

Below assumes `$OWNER` is your bootstrap-minted Owner key and
`$BASE` is `https://localhost:8443`.

### 1. Create a Reseller + Client

```bash
# Create reseller (Owner)
curl -sk -H "Authorization: Bearer $OWNER" -H 'Content-Type: application/json' \
     "$BASE/v1/resellers" \
     -d '{"reseller":{"name":"acme","password":"r3sellerpw"}}'

# Reseller logs in
RJWT=$(curl -sk "$BASE/v1/auth:login" \
        -H 'Content-Type: application/json' \
        -d '{"username":"acme","password":"r3sellerpw"}' | jq -r .access_token)

# Reseller creates a client
curl -sk -H "Authorization: Bearer $RJWT" -H 'Content-Type: application/json' \
     "$BASE/v1/clients" \
     -d '{"client":{"username":"alice","password":"alicepw"}}'
```

### 2. Owner sudo as alice

```bash
ALICE_JWT=$(curl -sk "$BASE/v1/auth:login" \
              -H "Authorization: Bearer $OWNER" \
              -H 'Content-Type: application/json' \
              -d '{"username":"alice","password":"anything"}' | jq -r .access_token)
# event log shows owner_sudo_login
```

### 3. Report usage from a node-side Agent

```bash
curl -sk -H "Authorization: Bearer $AGENT_KEY" -H 'Content-Type: application/json' \
     "$BASE/v1/usage:report" \
     -d '{
       "report": {
         "client_id":  "<alice UUID>",
         "node_id":    "<node UUID>",
         "agent_id":   "<agent UUID>",
         "upload":     1048576,
         "download":   4194304,
         "session_id": "sess-1",
         "client_ip":  "203.0.113.5"
       }
     }'
```

Response:

```json
{
  "decision": {
    "accepted": true,
    "quotaExceeded": false,
    "sessionLimitHit": false,
    "shouldDisconnect": false
  }
}
```

`client_ip` is read once for geo + session hashing, then **dropped**;
it is never persisted or logged.

### 4. Same call over native gRPC

```bash
grpcurl -insecure \
        -H "authorization: Bearer $AGENT_KEY" \
        -d '{"report":{"client_id":"…","upload":1048576,"download":4194304}}' \
        localhost:8443 hue.v1.UsageService/ReportUsage
```

## Phase 3 additions

### Key rotation environment

| Env var | Purpose |
|---|---|
| `HUE_ENC_KEYS` | Multi-key keyring: `"1:<hex32>,2:<hex32>"`. Takes precedence over `HUE_PASSWORD_ENC_KEY`. |
| `HUE_ENC_KEY_CURRENT` | ID of the active encryption key (must appear in `HUE_ENC_KEYS`). |
| `HUE_PASSWORD_ENC_KEY` | Legacy single-key (32-byte hex). Used as key ID 1 when `HUE_ENC_KEYS` is unset. |

See [auth.md → Key rotation](auth.md#key-rotation-hue_enc_keys) for the rotation procedure.

### mTLS

| Env var | Purpose |
|---|---|
| `HUE_MTLS_CLIENT_CA` | PEM CA file. When set + TLS is enabled, HUE requires client certificates (`RequireAndVerifyClientCert`). |

Agents provide their client cert via `agents.AgentDialOption(cert, key, caPEM)`.
See [auth.md → mTLS](auth.md#mtls--mutual-tls-for-agent-connections).

### DNS-01 ACME

`RequestACME` supports DNS-01 in addition to HTTP-01. Pass a
`DNS01Provider` (built via `cert.NewDNS01Provider("cloudflare" | "digitalocean" | "exec")`).
Required for wildcard certs or air-gapped nodes. See
[certificates.md → DNS-01 ACME](certificates.md#dns-01-acme).

### xray StatsService

`xray.Client.ReadStats` is now fully implemented: it calls xray-core's
`StatsService.QueryStats` with `pattern="user>>>"` + `reset=true`,
parses per-user upload/download deltas, and returns `[]agents.UsageDelta`.
No stub — requires xray to have `api` + `stats` in its config.

### RADIUS adapter

`pkg/agents/radius/` is a compilable scaffold (UDP listener + SyncConfig
snapshot cache). Packet decode stubs need a RADIUS codec — see
[agents.md → RADIUS](agents.md#radius-adapter-scaffold).

## Error model

All errors come back as gRPC `status.Status`. The grpc-gateway maps
to HTTP using the conventional table:

| gRPC code | HTTP | Used for |
|---|---|---|
| `OK`                 | 200 | success |
| `INVALID_ARGUMENT`   | 400 | proto validation, bad UUID, missing field |
| `UNAUTHENTICATED`    | 401 | missing / malformed / revoked token |
| `PERMISSION_DENIED`  | 403 | `authz.go` allow-list mismatch, reseller-scoping miss |
| `NOT_FOUND`          | 404 | resource doesn't exist |
| `ALREADY_EXISTS`     | 409 | unique constraint (e.g. duplicate `Client.username`) |
| `RESOURCE_EXHAUSTED` | 429 | quota / penalty / session limit / lockout |
| `INTERNAL`           | 500 | server-side failure |
| `UNIMPLEMENTED`      | 501 | RPC defined in proto but not yet wired |

Body shape: `{"code": int, "message": string, "details": [...]}`.

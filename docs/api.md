# API Reference

The wire contract is [`api/proto/hue/v1/hue.proto`](../api/proto/hue/v1/hue.proto).
Three services live there: `AdminService`, `UsageService`, `NodeService`.
Every RPC has a `google.api.http` annotation, so every gRPC method is
also reachable as a REST endpoint via grpc-gateway.

The OpenAPI spec generated by `make proto` is at
`gen/openapi/hue.swagger.json` and gets attached to every release as a
build artifact.

## Conventions

- All resource collections are mounted at `/v1/<plural>` (`/v1/users`,
  `/v1/nodes`, `/v1/managers`, `/v1/services`, `/v1/events`, `/v1/apiKeys`).
- Updates use `PATCH` with a `google.protobuf.FieldMask` (`update_mask`).
- Custom verbs follow Google AIP-136: `:resetUsage`, `:revoke`, `:report`,
  `:batchReport`, `:authenticate`, `:heartbeat`, `:stream`, `:sync`.
- Pagination is page-token-based: `page_size`, `page_token` request fields;
  `next_page_token` in responses.
- Authentication: `Authorization: Bearer <token>` header (HTTP) or
  `authorization: bearer <token>` gRPC metadata. See [auth.md](auth.md).

## Services at a glance

### AdminService — control plane

| RPC | Verb / path | Notes |
|---|---|---|
| `CreateUser` | `POST /v1/users` (body=`user`) | |
| `GetUser` | `GET /v1/users/{id}` | |
| `ListUsers` | `GET /v1/users` | filter: `status`, `manager_id`, `group`, `search` |
| `UpdateUser` | `PATCH /v1/users/{id}` (body=`user`) | partial update via `update_mask` |
| `DeleteUser` | `DELETE /v1/users/{id}` | |
| `ResetUserUsage` | `POST /v1/users/{user_id}:resetUsage` | |
| `GetUsagePlan` / `ListUsagePlans` / `GetActiveUsagePlan` | `GET /v1/usagePlans/...` | |
| `CreateNode` … `DeleteNode` | `/v1/nodes/...` | parallel set, plus `:resetUsage` |
| `CreateService` … `DeleteService` | `/v1/services/...` | `CreateService` returns the plaintext API key once (then forgets it) |
| `CreateManager` … `DeleteManager` | `/v1/managers/...` | parallel set, plus `:resetUsage` |
| `ListEvents` | `GET /v1/events` | filter: `type`, `user_id`, `manager_id`, `since`, `until` |
| `StreamEvents` | `GET /v1/events:stream` | server-streaming over chunked HTTP |
| `CreateApiKey` | `POST /v1/apiKeys` (body=`api_key`) | response includes plaintext token (returned once) |
| `ListApiKeys` | `GET /v1/apiKeys` | |
| `RevokeApiKey` | `POST /v1/apiKeys/{id}:revoke` | |
| `HealthCheck` | `GET /healthz` | also implements `grpc.health.v1.Health` |

### UsageService — data plane (called by nodes)

| RPC | Verb / path | Notes |
|---|---|---|
| `ReportUsage` | `POST /v1/usage:report` (body=`report`) | one usage record |
| `BatchReportUsage` | `POST /v1/usage:batchReport` | up to 1000 reports per call |
| `SyncUsers` | `GET /v1/users:sync` | initial-state pull on node startup |

### NodeService — node bootstrap

| RPC | Verb / path | Notes |
|---|---|---|
| `AuthenticateNode` | `POST /v1/nodes:authenticate` | exchange one-time provisioning token for session token (currently returns Unimplemented) |
| `Heartbeat` | `POST /v1/nodes:heartbeat` | periodic counter sync + disconnect-command fetch |

## End-to-end example

The plaintext API key was minted by `HUE_BOOTSTRAP_TOKEN` at first
startup; export it as `$TOKEN` first.

### 1. Create a user

```bash
curl -sk -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     https://localhost:8443/v1/users \
     -d '{
       "user": {
         "info":        { "groups": ["test"] },
         "auth_method": { "username": "alice", "password": "p4ssw0rd" }
       }
     }'
```

Response includes the new `info.id` (UUID) and a populated `lifecycle`.

### 2. Report some usage (as the central service, for now)

```bash
curl -sk -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     https://localhost:8443/v1/usage:report \
     -d '{
       "report": {
         "user_id":    "<UUID from step 1>",
         "upload":     1048576,
         "download":   2097152,
         "session_id": "demo-session",
         "client_ip":  "203.0.113.5"
       }
     }'
```

Response: `decision.accepted = true`. The `client_ip` is dropped on the
server side immediately after geo + session processing — it is never
written to disk and never logged.

### 3. Same call over native gRPC

```bash
grpcurl -insecure \
        -H "authorization: Bearer $TOKEN" \
        -d '{"report":{"user_id":"<UUID>","upload":1048576,"download":2097152}}' \
        localhost:8443 hue.v1.UsageService/ReportUsage
```

Both calls hit the **same** Go function via the same interceptor chain,
including auth and protovalidate.

## Error model

All errors come back as standard gRPC `status.Status`. The grpc-gateway
maps them to HTTP using the conventional table:

| gRPC code | HTTP status | Used for |
|---|---|---|
| `OK` | 200 | success |
| `INVALID_ARGUMENT` | 400 | proto validation, bad UUID, missing field |
| `UNAUTHENTICATED` | 401 | missing / wrong / revoked token |
| `PERMISSION_DENIED` | 403 | per-actor scope check failed |
| `NOT_FOUND` | 404 | resource doesn't exist |
| `ALREADY_EXISTS` | 409 | unique constraint violation |
| `RESOURCE_EXHAUSTED` | 429 | quota / penalty / session limit |
| `INTERNAL` | 500 | server-side failure |
| `UNIMPLEMENTED` | 501 | RPC defined in proto but not yet wired (Node bootstrap) |

The body shape is always `{"code": int, "message": string, "details": [...]}`.
